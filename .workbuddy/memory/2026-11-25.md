## 阶段 4 本地生产系统（已完成，56 测试全过）

### MPT 核心接口审计结论（关键，供后续复用）
- `video.generate_video(video_path, audio_path, subtitle_path, output_file, params, bgm_file_override)`：
  **接受的是文件路径**，只要 PetAI 产出「合成好的无声素材视频+音频+SRT」即可复用，不改 MPT 核心。
- `video.combine_videos(combined_video_path, video_paths, audio_file, video_aspect, video_concat_mode, max_clip_duration, ...)`：
  把本地图片/视频路径拼成无声视频；对本地任意路径图片会自动清理 EXIF，兼容本地素材。
- `VideoParams.video_aspect=VideoAspect.portrait` → 默认就是 **1080×1920 / 9:16**。
- `app.utils.utils.get_ffmpeg_binary()`：统一 ffmpeg 解析（PATH→imageio-ffmpeg 内置二进制，本项目内置可用）。
- `voice.tts()` 走 edge/azure/elevenlabs 等**在线付费**链路 → PetAI 绝不调用它。
- `subtitle.create()` 用 faster-whisper 本地模型；`subtitle_provider=edge` 失败时 MPT 已有「禁止自动切 whisper」先例。

## 时长自动对齐（第三轮，用户反馈"脚本生成后字幕和视频时长不一致"）

根因不是单点：脚本目标时长 ≠ 真实配音时长 ≠ MPT 素材拼接时长（含安全余量）。
新增 PetAI/services/alignment_service.py，以真实配音为唯一时间基准做三层对齐：
1. align_srt_to_duration：任意 SRT 时间轴缩放到音频时长，末条精确对齐；修重叠/倒序/越界。
2. align_video_to_audio：ffprobe→ffmpeg -i→MoviePy 三级探测；成片偏长用 -t 裁剪，
   偏短用 tpad 克隆末帧；容差 0.3s 内不重编码。
3. verify_alignment：三者时长与 max_delta，写入 productions.alignment_report（含幂等迁移列）。
VideoService.produce/recompose 接入；新增 fix_alignment(production_id) 供已有视频一键校正。
配置 [video] auto_align=true / align_tolerance=0.3，默认开启；界面显示对齐报告与校正按钮。

关键约定：produce 的真实音频探测失败才回退调用方 audio_duration；真实环境永远以文件为准。
验证：PetAI 69 passed（新增 13 项对齐测试）；AppTest 9/9；核心抽验 81 passed/5 skipped/31 subtests；
真实 FFmpeg E2E：8s 音频 + 10s 视频 + 5s SRT → 三者均 8.00s、max_delta=0.0、aligned=True。
边界：精确裁剪需重编码（crf 20），可用 align_tolerance 调大规避；探测全失败则保留原成片。

## 修复豆包操作后不切回、无反馈
用户反馈：生成图片素材后不自动继续，操作完没反馈，每次要手动切回网页。
根因：
- generate_image/generate_video 把豆包最大化切前台后从不切回原窗口。
- 生成成功立即 st.rerun()，普通 success 被清掉，用户回来看不到结果，以为没执行。
- image_wait 默认 30s < 实测 38s，常未生成完就点下载 → 流程中断。
- Windows 前台锁定让后台进程 SetForegroundWindow 失败，原实现直接抛错中断。
修复：
- 新增 DoubaoDesktopService.generation_session()：记录原前台窗口+豆包位置，结束还原豆包
  → 切回原窗口 → winsound 提示音；切回失败则最小化豆包兜底。
- _activate 多重回退：最大化+短暂置顶 → AttachThreadInput → SwitchToThisWindow → 点标题栏；
  GetForegroundWindow()==0（非交互会话）不再误报失败。
- DoubaoScriptService.generate_json 套同一会话，选题/脚本也自动切回。
- image_wait 30→45s（settings/toml/example 同步）。
- WebUI 加 _flash()：提示跨 rerun 保留；向导第4步生成后自动加入 w_materials。
验证：PetAI 90 passed；AppTest 9/9；新增 2 项恢复顺序测试。
注意：执行环境是非交互会话，GetForegroundWindow 可能为 0，真实切窗需用户本机验证。

## 多分镜方案与多素材合成（差距修复）
用户反馈：分镜应该是多个、素材也该多个，可以让豆包设计视频分镜方案，现在和原版差距大。
根因：
- prompt 没限制分镜数，豆包常给 2-4 条且缺 duration/shot；
- 分镜生成后完全没被使用：素材为空时 select_local_first(count=1)；
- MPT video_concat_mode 默认 random，多素材也会打乱；
- 界面没有分镜概念。
改造：
- prompt 要求 6-8 镜头，含 scene/duration/shot/description/asset_keyword/caption。
- ScriptService._normalize_storyboard：不足 4 条按句子补足，时长按权重归一到目标时长
  （坑：补足项塞平均值会超总时长，改为统一权重缩放 + 误差分摊），上限 8 条。
- LocalAssetService.plan_for_storyboard：关键词逐镜匹配，通用词 cat/dog/pet 不计分；
  同分优先未用/少用；不足轮换并标 matched=False。
- VideoService.build_video_params 固定 sequential；produce/produce_bilingual 加 storyboard，
  素材为空自动配齐。
- DoubaoDesktopService.generate_for_storyboard：按分镜批量生成，整批一次 generation_session；
  拆分 _generate_image_once/_generate_video_once 支持 manage_session=False。
- WebUI：脚本页/向导展示分镜表；第4步「按分镜自动配」「按分镜豆包批量生成」；
  第6步显示素材缺口并传 storyboard_zh/en。修复 use_container_width 弃用警告→width="stretch"。
验证：PetAI 100 passed；AppTest 9/9；真实合成红/绿/蓝三段 6s + 15s 音频 → 15.0s，
抽帧 2s 红(250,0,0)、8s 绿(0,124,0)、14s 蓝(0,0,250)，顺序正确。MPT 核心零改动。
边界：每段时长仍由 clip_duration(5s) 控制，与原版一致；素材不足会复用，建议豆包按分镜补足。
